## 本机配置与环境

- CPU：AMD Ryzen 9 8945HX with Radeon Graphics，主机32个逻辑核心。
- 内存：DDR5，32 GiB；实际执行在本机 Ubuntu WSL2，最新批次开跑前记录的 MemTotal 为15968388 KiB，约15.23 GiB。
- SageMath 10.7：精确代数、原方程与根盒验算；Python 3.12.3：证明程序与控制器。核对脚本使用 Python 标准库。
- 未在本次运行中临时安装工具。早期入选运行引用同机共享环境记录，未保存每次开跑时的独立硬件快照。

## 算法版本

证明引擎的基础代际是 DGC v62。`DGC v62-F` 对应内部冻结代码 `radius-code-feedback-v1`，加入新来源几何反馈；`DGC v62-G` 对应 `radius-code-gmp-v1`，在该版本上加入局部证书验证的 GMP 精确有理数后端。最小多项式引擎独立编号，本次入选为 MinPoly v15，内部代码名 `minpoly-code-v15`。名称不代替代码身份，原运行文件的 SHA-256 在机器可读记录中列出。

程序从 n 输入开始，重新发现构型和根系统，生成并检查半径证书；代数引擎从该新系统提取不可约多项式并验证原始有理方程和根盒。整合控制器最终要求双方使用同一来源根系统。重叠版本可以在根系统通过检查后开始代数计算；临时结果必须等待最终证书与来源绑定。

这是基于既有研究算法和条件引理的程序运行；没有重新从题目研发算法，也没有以公开参考系数或旧构型作为求解输入。源码目前不公开。

## 计时与主要阶段

每个案例的控制器启动为 T+00:00:00；T+189.333 秒保存最终绑定结果。半径阶段 189.250 秒，代数阶段 36.096 秒，两阶段重叠 36.096 秒。完整用时由控制器单独测量，包含启动、证明与代数消费者、最终同根绑定及结果写出；重叠阶段不得相加。

计算 SHA-256 与求解后的参考复核另行进行，不计入计分用时。这里的冷启动指新进程从 n 开始，不代表重启操作系统或清空全部系统缓存。研发耗时、费用和任务系统累计耗时未记录。

分数采用与模型测试相同的计分公式：`ROUND_HALF_UP(200 + 100 × log₂(21600 / t))`，其中 t 是完整程序用时（秒）。分数越高越好；6小时为200分，用时每减半增加100分。两类记录使用同一分数尺度比较完成效率，报告保留各自的起始条件、算法版本和计算环境。

## 核验与交付边界

运行时实际执行半径与代数消费者，并检查最终来源相同；随后对本例核对全部系数、不可约性及同一根，检查精确区间所确定的小数点后20位舍入，再调用网站原脚本和独立规范 JSON 重建核对哈希。

本次发布准备时，没有重跑求解器；重新检查入选历史结果与本例最新结果的全部系数相同、认证根区间相交，并用网站共用脚本重算指纹，结果与登记值相同。既有来源准入与有限分类信任基础仍保留，没有新增独立数学审查或形式化证明。
